# S11：上下文压缩与仓库探索成本

## 改动

- `codepilot.agent._fit_context` 压缩旧工具结果时，保留首尾证据摘要和原始字符数；上下文仍超限时，再缩短旧摘要。工具消息 ID 保持不变，补丁和测试结果不会因摘要而被当成新工具消息。
- 系统提示允许模型跳过与明确任务无关的仓库图和全局搜索；证据足够后结束探索，文件内容没有变化时避免重复读取相同范围。补丁通过配置测试和差异检查后应直接总结。

## 验证

- 上下文压缩回归覆盖首尾证据保留、重复压缩、原始字符数和工具调用 ID。
- NN 完整测试：`D:\Anaconda3\envs\NN\python.exe -m pytest -q --basetemp .tmp/pytest-s11-complete`，**100 passed**。
- Click 8.3.1 上游案例额外运行 3 次：316,604 Tokens、估算 `$0.084900`，累计评测约 142 秒。三次都没有达到 Agent 完整成功状态。
- 最新一次在 11 步、105,840 Tokens、估算 `$0.030778` 后写入补丁；独立可见和隐藏测试都通过，但 Agent 自己的配置测试和最终答复未完成，仍按失败记录。
- 另外两次分别在 13 步、102,000 和 108,764 Tokens 后因预算停止。详细轨迹与成本见 `reports/public-click3145-s11-*`；评分见 `reports/trajectory-score-s11/`。

## 结论

证据摘要保留和更有条件的检索提示能让 Agent 在较少步数内接近正确修复，但当前样本很小，Token 上限和步数配置不同，不能据此声称成本已稳定降低。Click 任务仍会过度探索；即使补丁通过独立测试，Agent 也可能未完成自己的验收闭环。下一步应分析工具循环的停止条件和测试收尾状态，并用配对、固定预算的真实模型评测验证。
