# S14：模型请求预算与中断恢复

## 目标

修复 S13 公开案例中暴露的缺口：18k Token 限额只在模型完整返回后检查，导致单次请求可越过限额，运行在产生补丁前终止。

## 实现

- 发送请求前，将消息、工具定义的 UTF-8 字节体积折算为 Token 估计，并增加协议边界余量。
- 剩余预算不足以容纳预留输入和至少一个输出 Token 时，不调用模型。
- 将剩余预算扣除输入预留后的值，与模型配置的输出上限取较小值，并传入 Chat Completions 请求。
- 继续依据服务端实际 usage 做事后核对；若供应商统计值超过预留，运行立即以预算超限结束。
- 把已返回的模型响应、累计 usage 和待执行工具位置写进 AgentState 快照。恢复时先处理已保存响应，避免再次请求模型。
- 工具结果和下一个待执行位置一起写入快照；LangGraph/SQLite 运行状态可保存和恢复这些字段。

## 边界与限制

输入 Token 预留使用 UTF-8 字节数除以 3 的估算和固定协议余量，不是供应商 tokenizer 的精确计数。首次 S13 复测校准发现，直接把每个字节算作一个 Token 会过度预留：Flask 第二次请求估算 13,642，而服务端报告 3,894。校准运行在 6,233 Token 处提前停止，轨迹保留在 `reports/public-s13-postfix-calibration/`。服务端 usage 仍是最终核对值。输出 Token 通过 API 输出上限约束；若兼容服务忽略上限或返回 usage 不符，事后检查会标记超限，但无法撤回已经发生的费用。

崩溃若发生在工具产生副作用后、对应快照落盘前，外部工具无法提供通用的 exactly-once 保证。快照提交后的恢复会从下一项工具继续。

## 验证

- 小于请求预留的预算：模型调用次数为零。
- 预算只剩 5 Token：模型收到的 completion 上限为 5。
- 模拟服务端 usage 超过预算：运行结果标记 `budget_exceeded`。
- 模拟模型响应已落盘后进程退出：恢复过程不重放该模型请求，并继续执行工具。
- 修复公开 sdist 中被 `.gitignore` 忽略的 `src/**/_version.py` 暂存，确保干净工作副本和隐藏测试都能导入 urllib3 源码。
- 全量测试：108 项通过。

## 后续实验

S13 原始 `0/4` 结果保持不变。严格预算修复后对相同冻结题集的复测必须写入独立报告；新的公开 holdout 则需在首次模型调用前冻结并提交，不能据其结果调试提示词或测试。
