## S18 上下文预算诊断

Click #3084 原失败记录保持不变。先前提高 Token 上限重跑仍因压缩后上下文略高于限制而在第 11 步停止，已返回 usage 为 44,699 Token、估算 `$0.003702`。修复多轮压缩后，单独诊断重跑维持了 10,000 字符上下文上限，并推进到第 13 步；之后模型请求超过三分钟无响应，手动中断。其已返回 usage 为 59,902 Token（输入 53,061、缓存输入 34,432、输出 6,841），估算 `$0.007002`，不含中断请求费用；没有补丁或测试。

此前提交 `0849c28` 让 `_fit_context` 重复压缩旧工具结果，直到上下文满足上限或没有可压缩内容。但回归轨迹又暴露无进展死循环：助手消息已替换成压缩占位文本后，每轮仍被计作一次压缩，导致 Agent 卡在本地上下文整理，不会发出下一轮模型请求。提交 `24644ce` 只在内容实际变化时才计进展，并增加不可压缩消息超限时退出的测试。

提交 `0f03185` 修复另一处证据丢失：`read_file` 和 `search_code` 缓存命中原先只提示“参考前次结果”，但旧观察可能已被压缩。现在缓存命中会重发原证据；system prompt 提示模型使用本轮返回值。新增回归测试覆盖旧证据压缩后通过缓存重新取回。

同一提交将 OpenAI 客户端 `max_retries` 设为 0，避免 SDK 自动重试把单次超时拉长。最终重跑用 `LLM_TIMEOUT_SECONDS=45`、60k 总 Token、16 步、240 秒任务时限；任务在 Token 预算护栏处正常结束，未出现请求超时。

定向测试 **48 passed**；全项目测试 **120 passed in 39.78s**。工具缓存修复减少证据丢失风险，但 urllib3 最终重跑仍反复读源码并在第 11 步触发 Token 预算保护；模型没有编辑或测试。

## 连续探索护栏与单项重试

为抑制无代码变化的重复探索，Agent 在连续两轮只读后向下一轮模型请求加入中文提醒；连续四轮只读后暂停为 `needs_user_input`，请用户补充方向。该护栏不要求模型补丁，也不把暂停报告成成功。新增脚本模型测试覆盖提醒送达、四轮熔断和不强制补丁；提醒放在独立 developer 消息中，避免被旧工具观察压缩掉。

Docker Desktop 版本 `29.1.3` 和镜像 `codepilot-public-runner:20261020` 均可用。使用 80k Token、4,000 字符上下文、12 步、240 秒参数，只重试 urllib3 #3653。结果仍为 **0/1 accepted**：第 4 轮只读后触发护栏，无补丁、无测试。调用 6 次（读文件 3、搜索 1、其他只读 2），总计 11,244 Token（输入 10,717、缓存输入 8,064、输出 527），非高峰费用 `$0.000738`，峰时费率估算 `$0.001476`，Agent 10.5 秒、全流程 15.8 秒。低于本轮 `$0.03` 成本上限。

该真实重试使用旧提醒投递方式；轨迹表明提醒可能随工具观察压缩。之后已改成独立 developer 消息，并通过脚本模型单测和全回归验证。按“单项重试”限制，本轮不再发起第二次真实模型调用。完整记录在被忽略的 `reports/public-s20-explore-guard-20261020/`。
