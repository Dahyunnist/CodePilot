## 预算行为

四次运行都设置 `max_total_tokens=18000`，实际使用量为 20,277 至 24,325，超出 12.7% 至 35.1%。原因可从 `Agent.run` 确认：Agent 先等待模型完整返回，再把实际 Token 加入累计值并检查限额。该设置是调用后的停止条件，不能阻止单次模型请求跨过限额；模型上下文仍受 30,000 字符上限约束。

此行为需要后续单独改进。S13 结果不得用于调提示词或重跑这组案例；严格预算修复后，应使用新冻结案例集验证。

## 基线与容器

- Flask 源码基线：两项 issue 回归测试失败，`tests/test_blueprints.py` 57 项通过。
- urllib3 源码基线：数据正确性测试通过，64 MiB 未消费尾部产生约 64 MiB 峰值额外分配；隐藏基线也因内存分配断言失败。
- 可见和隐藏测试都在独立 Docker 容器中验证。容器断网、只读、非 root、512 MiB、1 CPU；镜像定义见 [public-runner.Dockerfile](../../docker/public-runner.Dockerfile)。
- 真正模型执行均未生成 patch，因此四次运行的独立可见/隐藏验收字段都为失败或未执行。

## 数据边界与偏差

S13 案例、问题说明和测试在首个模型调用前提交。首个 Flask 模型调用后，urllib3 上游测试证书/私钥被工作区安全检查拦截；我提交了精确排除清单，才运行 urllib3 的首次模型调用。目标代码、测试、提示词和预算没有因此改变，但案例打包元数据在首个模型请求后更新。因此把四次结果视为探索性证据，不作严格预注册实验或统计推断。

Flask 和 urllib3 使用 PyPI 官方 sdist，版本与 SHA-256 见 [S13 预注册说明](stage-S13-preregistered-public-benchmarks.md)。没有把 PyPI 版本误标为 Git commit。被排除文件仅是与目标无关的 `.env`、测试证书和私钥夹具；排除路径写在结果 JSON 中。原始 trace、测试日志和 JSON 结果保留在 `reports/public-s13-attempt-*`，未提交。
